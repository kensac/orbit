# Portable API export

Build with `go build -o /tmp/orbitexport ./cmd/orbitexport`. Use the same `ORBIT_URL`, `ORBIT_OIDC_ISSUER` and `ORBIT_OIDC_CLIENT_ID` as [orbitctl](../orbitctl/README.md). The public authentik provider must support device-code login and be accepted by Orbit. Sign-in prints a verification URL and user code; the access token remains in memory and is never written to the bundle. HTTPS and redirect protections are shared with the terminal client.

```sh
orbitexport export assistant ./assistant-export.zip
orbitexport -timeout 20m export finance ./finance-export.zip
orbitexport verify ./assistant-export.zip
orbitexport inspect ./assistant-export.zip
unzip -p ./assistant-export.zip manifest.json
```

Each export selects one agent. It reads its current loaded definition and legacy memory, context, active current profile and agent entries, active current entries in its attached topics, and attached skills at the versions the context reported. Both active and archived conversations, including the learning conversation, are paginated; each conversation's thread pages are paginated independently. Thread JSON carries message and run IDs, reports, attachments metadata, questions and actions exposed by that endpoint. Skill JSON carries its content and files. Agent definition JSON is preserved without decoding away additional fields such as `chat` and `sandbox`; a chat agent's thread contains its final replies in the existing `report` field. No server writes are performed.

The ZIP contains `manifest.json` and numbered JSON members under `resources/`. Format version 1 records the selected agent, start/finish times, every requested endpoint and pagination cursor, resource coverage/error class, member byte lengths and SHA256 hashes. The API's identifiers and revisions remain intact in JSON payloads; a bounded manifest index also includes identities when available. Members are preserved page by page in API order, rather than pretending separately fetched pages are a single snapshot. `verify` bounds the central directory before loading ZIP metadata and rejects unsafe, duplicate or unlisted members, inconsistent metadata, size differences and digest mismatches. The emitted format uses regular files in a single-disk ZIP without ZIP64 or archive/member comments; verification rejects those unsupported extensions. Verification proves integrity against the included manifest, not authenticity, completeness or restorability.

`inspect BUNDLE.zip` runs the same strict integrity verifier as `verify` and emits the validated manifest as one JSON object, including resource coverage, cursors, errors, exclusions and explicit completeness flags. It needs no server URL or authentication, performs no extraction or writes, and accepts partial exports whose manifest describes incomplete coverage. Verification or output-size failure emits no JSON and exits nonzero; output is limited to 16 MiB including its newline (a manifest whose JSON escaping exceeds that limit is refused). Successful inspection proves neither authenticity nor completeness nor restorability.

`backup_complete` and `consistent_snapshot` are always false. This is a portable API export, not a database backup. Historical definitions, memory and skill versions, retired entries, upload bytes, run artifacts, journals, session transcripts and deployment configuration are excluded. Persistent conversation workspaces are also excluded: no workspace file listing or bytes, snapshot metadata/archive, retained sandbox HOME or hidden `.orbit` session state is fetched. A chat export therefore preserves the selected API conversation data without preserving a resumable chat workspace. The `/conversations/{id}/files` endpoints expose the latest workspace snapshot separately and are outside this export. Concurrent changes can alter context or move conversations between pages; no API transaction spans the export. Only the scopes and skills visible when context was read are selected. Memory entry lists have an API maximum of 1,000 with no cursor; a response containing that many entries is explicitly marked possibly truncated. A successful resource coverage flag means these bounded requests completed, not that all stored data was captured.

The default overall timeout is 10 minutes, configurable with `-timeout`; each request also has a 30-second deadline. Limits are 16 MiB per response, 256 MiB of response JSON and 1,000 responses per export. Pagination cursors above 1,024 bytes or containing nonprintable/non-ASCII bytes are refused, and identifiers above 256 bytes are refused. A byte/page limit, repeated or inconsistent cursor, invalid resource, missing skill, API failure or cancellation produces an incomplete manifest and a nonzero exit. Previously fetched data is retained in the published partial bundle; inspect the manifest's resource coverage and cursor before choosing a new output path to retry. Authentication failure before export begins does not create a bundle.

Publication stages a mode-0600 file beside the destination, closes and syncs the ZIP, then atomically links it to the requested new path. Existing paths are never overwritten, including paths created while export runs. The destination filesystem must support local hard links; unsupported filesystems return an error without a published export. Interrupted staging files are not a completed bundle. The archive contains private conversation and memory data; keep it in storage appropriate for those contents. There is no import or restore command.
