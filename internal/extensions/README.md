# Extension package validation

`go run ./cmd/orbitextension validate <directory>` reads a local package and prints its manifest, SHA-256 package/manifest digests, total bytes and file count as JSON. It never installs or executes a package. A validation failure prints its reason to stderr and exits nonzero. No extension runtime, deployment pin, agent grant or configuration integration is enabled by this command. The directory must be immutable during validation; the returned digest is not a handle that makes later reads safe.

The validator implements the initial manifest subset proposed in [the design](../../docs/plugins.md): protocol `orbit.extension.v1`, lowercase IDs/operation/input/endpoint names, numeric `major.minor.patch` versions, native runtime only, one relative entrypoint, and 1 through 32 uniquely named operations. Each operation requires `name`, `kind`, `description`, `input_schema`, `output_schema` and `limits`. `inputs` optionally declares unique logical slots. Only actions require an `endpoint` logical slot; it grants no destination access. Multiple operations may share a kind or logical binding name because each operation's bindings are separate.

Limits require positive `timeout_ms` (at most 30000), `memory_bytes` (at most 268435456), `input_bytes` and `output_bytes` (each at most 16777216). These values are validated declarations only; no process exists here to enforce them. The implementation does not yet include all resource/profile fields a future runtime will need.

Schemas accept a single `type`, optional scalar `enum`, and type-specific fields. Objects require `properties` and `additionalProperties: false`, with optional unique `required` names declared in properties. Arrays require `items` and `maxItems` (at most 10000), with optional `minItems`. Strings require `maxLength` (at most 1048576), with optional `minLength`. Numbers and integers require `minimum` and `maximum`; integer bounds are integral. Booleans and null have no extra fields. Numeric text is bounded before exact rational parsing, including exponents between -308 and 308; string lengths count Unicode characters. Enum values must meet type and bounds and be distinct, including numeric equivalence. Unsupported keywords, references, recursive or over-depth schemas, unknown fields and duplicate JSON keys fail validation.

Package limits are 256 KiB for the manifest including schemas, 32 MiB for all regular-file bytes, 256 regular files, 512 directory entries and 16 nested path separators. Files must be regular, singly linked, and free of setuid/setgid/sticky bits; symbolic links and special files fail validation. Entrypoint validation checks an executable permission bit and the structural header of a 64-bit little-endian Linux ELF executable or PIE for x86-64 or arm64. It does not load the file, verify its full ELF layout/dependencies, or prove compatibility with a sandbox image. The inert fixture under `testdata/reducer` contains only an ELF header and is deliberately not a runnable integration example.

The package digest is SHA-256 over regular files in lexical slash-path order. For each file, hash its path byte length (big-endian uint64), path bytes, permission bits (big-endian uint32), content byte length (big-endian uint64), and raw content bytes. Empty directories and timestamps are excluded. The separate manifest digest hashes its exact file bytes. Both are content identities, not signatures, trust decisions or execution authorization. Installation must eventually copy and verify immutable bytes within its own boundary, rather than trusting a previously validated mutable directory.

Run `go test -race ./internal/extensions ./cmd/orbitextension` for malicious manifest/schema cases, link and FIFO rejection, package resource ceilings, content identity and command behavior. Sandbox isolation, action approval and external endpoint tests remain future work because this slice has no execution or effects.
